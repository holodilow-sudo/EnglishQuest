# Сборка APK в GitHub

[Открыть Build APK](https://github.com/holodilow-sudo/EnglishQuest/actions/workflows/build-apk.yml).

## Проверка изменений

При изменении приложения, Android-кода или сборщика в `main` и pull request автоматически проверяется учебный курс и собирается APK без подписи. Для этих запусков ключи недоступны. Результат `unsigned-apk-N` хранится 7 дней и предназначен для проверки сборки, а не установки.

## APK для установки

1. Откройте Actions → Build APK → Run workflow.
2. Выберите ветку `main` и включите `Sign APK and prepare a draft release`.
3. После успешного завершения откройте ссылку **Draft ready for approval** в сводке сборки или раздел Releases. Для новой версии там автоматически появится черновик с APK, SHA-256 и `build-info.json`.
4. Проверьте APK и описание. Только после согласования с владельцем откройте черновик, при необходимости дополните описание и нажмите **Publish release** (стабильный выпуск, отметить как Latest).

APK также доступна в `installable-apk-N` из Artifacts: скачайте и распакуйте ZIP.

В архиве находятся APK, её SHA-256 и `build-info.json`. Подпись должна совпадать с ранее выпущенными версиями; другой ключ приводит к ошибке. Артефакт хранится 30 дней. Для подписи сначала нужно настроить закрытые секреты, описанные ниже.

Перед следующим выпуском увеличьте `android:versionName` и `android:versionCode` в `android/src/main/AndroidManifest.xml` (исходная версия 1.2.2 / 6), согласуйте изменения и запустите подписанную сборку. Черновик получает тег `vX.Y.Z` и привязывается к точному коммиту сборки. Черновики недоступны обычным пользователям и не предлагаются приложением как обновление. Автоматической публикации нет: только после отдельного согласования публикуется стабильный Release, и приложение обнаруживает его. Не удаляйте приложение на телефоне и не очищайте данные.

Если версия уже опубликована, создание черновика пропускается, а опубликованные файлы остаются прежними. Повторный запуск может дозагрузить недостающие файлы того же черновика; совпадение контрольных сумм проверяется. Если коммит или существующий файл отличается, задача остановится без перезаписи: сначала нужно проверить прежний черновик. Для сравнения versionCode у последующих опубликованных релизов сохраняйте `build-info.json` рядом с APK.

Задача `draft-release` работает только после успешной подписи и получает кратковременный GitHub-токен с `contents: write` для создания черновика и загрузки файлов. У неё нет доступа к окружению подписи и закрытому ключу. В коде нет вызова публикации релиза; все новые релизы создаются с `draft: true`.

## Закрытая подпись

В Settings → Environments создайте `android-signing`. Ограничьте deployment branches значением `main` (Selected branches and tags → branch main). В Environment secrets добавьте:

- `ENGLISHQUEST_KEYSTORE_BASE64` — существующее хранилище подписи в base64;
- `ENGLISHQUEST_STORE_PASSWORD` — существующий пароль хранилища;
- `ENGLISHQUEST_KEY_PASSWORD` — только если пароль ключа отличается.

Base64 сам по себе не шифрует данные: значение хранится исключительно в GitHub Secrets. Не вставляйте его в исходники, issues, команды с журналированием или файлы сборки. Сохраните локальную резервную копию исходного ключа отдельно от репозитория. Новый ключ для этого приложения создавать нельзя.

Подписывающая задача запускается только вручную из `main`, на отдельной временной машине, без checkout исходников. Ключ передаётся только шагу подписи, восстанавливается во временный файл и удаляется в `finally`; загружаются только APK, контрольная сумма и метаданные. У задач проверки и подписи GitHub-токен имеет лишь чтение содержимого; право записи выдаётся только отдельной задаче подготовки черновика. Сторонние Actions закреплены полными SHA. Доступ к изменению workflow и `main` оставляйте только доверенным людям: такой доступ позволяет изменять код, использующий секреты.

Ожидаемый SHA-256 сертификата прежних APK:
`78675df290e5190b39be40c609fffc3060e0b754462a2cbfd2172cf35c9ad246`.

Собирается обезличенная публичная версия исходников; подробности об исключённых личных настройках и двух аудиофразах — в [инструкции разработчика](source-development.md). Файл `source-manifest.json` описывает первоначальный опубликованный архив исходников, а не последующие изменения репозитория.
